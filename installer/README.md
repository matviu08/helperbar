# Інсталятор HelperBar

`../Build-Installer.ps1` збирає Windows x64 пакет із вбудованим .NET за допомогою Inno Setup 7. Перевірено з SDK 10.0.301, runtime 10.0.9 та Inno Setup 7.1.1. Для першої збірки потрібен доступ до NuGet. Компілятор Inno Setup встановлюється окремо з офіційного сайту; скрипт не завантажує й не запускає сторонніх інсталяторів.

- `HelperBar.iss` — український/англійський майстер, встановлення для поточного користувача, ярлики, коректне закриття застосунку, захист від зниження версії та видалення без втрати AppData.
- `Make-Icon.ps1` — відтворюване створення значка з очима у 7 розмірах; готовий `Assets/HelperBar.ico` зберігається у Git.
- Production AppId: `{D87FEAF1-AE71-4A34-9894-EA87F98A5F51}`. Не змінювати між версіями: він пов'язує оновлення й запис видалення.
- QA AppId: `{377B6959-994F-4E0F-982A-A441808379BA}`. Тестовий інсталятор не змінює автозапуск, але користується тим самим mutex; перед тестом закрий звичайний HelperBar.
- У production наявний власний запис автозапуску переноситься на встановлену програму. При видаленні прибирається лише запис, що точно вказує на цю копію. Автозапуск, який був вимкнений, залишається вимкненим.

## Перевірка

Зібрати QA-пакет: `./Build-Installer.ps1 -InstallerTest`. Запустити `./installer/Test-Installer.ps1`: він встановить тестовий пакет в окрему папку `artifacts`, перевірить контрольні суми всіх файлів, ярлики, реєстрацію видалення, самоперевірки, WPF-рендер і повторне встановлення, після чого видалить тестову програму. Особисті налаштування не створюються й не змінюються; тестовий файл у папці встановлення має залишитися після видалення.

Кожен звичайний пакет збирається з нової папки `artifacts/package/<version>-<id>`, а не з робочої `dist`, де можуть бути особисті дані. Версія береться з `HelperBar.csproj`. Перед випуском треба також перевірити встановлення/запуск на чистій Windows без системного .NET; локальна перевірка використання власного runtime не замінює окремої машини.

## Публікація для сайту

1. Зібрати production-пакет з гілки `helperbar` і перевірити його.
2. Створити GitHub Release із тегом, наприклад `v0.13.1`, що вказує на перевірений коміт `helperbar`.
3. Прикріпити `HelperBar-Setup-x64.exe` та `SHA256SUMS.txt` як assets. Особисті дані й тестові звіти не публікувати.
4. Після публікації підключити кнопку сайту в `main` до `https://github.com/matviu08/helperbar/releases/latest/download/HelperBar-Setup-x64.exe` і перевірити завантаження.

Сам скрипт нічого не публікує. Ім'я EXE стабільне, тому посилання на останній звичайний випуск можна залишати незмінним. Поточний пакет не підписано: цифровий підпис видавця потрібно налаштувати окремо. Контрольна сума перевіряє цілісність файлу, але не замінює підпис.
