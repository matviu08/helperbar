# HelperBar

HelperBar — анімований острів для Windows, написаний на C# / WPF: живі очі, музика, персональна головна, заряд пристроїв і сповіщення. Версія **0.13.1** додає інсталятор із вбудованим .NET та зберігання даних в AppData. Профілі «Моє», «Робота», «Музика» та «Ігри» мають незалежні віджети, кольори, силу анімацій і параметри сповіщень. Нотатка, справи, поличка файлів і запущені таймери спільні для всіх режимів.

Детальний план наступних функцій, пріоритети, критерії готовності й порядок роботи: [ROADMAP.md](ROADMAP.md).

## Гілки репозиторію

| Гілка | Призначення |
| --- | --- |
| `main` | Сайт проєкту; його розробка — окремий етап |
| `helperbar` | Вихідний код Windows-програми, README, план розвитку та перевірки |

Ці гілки мають незалежне призначення й не зливаються одна в одну. Щоб завантажити код програми, вибери `helperbar` у списку гілок на GitHub. Сайт у `main` зможе посилатися на цю гілку та готові випуски програми.

У Git зберігаються вихідний код і документація. Папки збірки `bin/`, `obj/`, `dist/`, `artifacts/`, локальні дані `data/`, звіти `qa/` та ярлики `.lnk` виключені через `.gitignore`. Після завантаження коду програму потрібно зібрати — інструкція нижче.

## Встановлення й запуск

Готовий інсталятор має назву `HelperBar-Setup-x64.exe`. Потрібні Windows 10 22H2 (build 19045) або новіша версія Windows із підтримкою x64. .NET Desktop Runtime включено в пакет; додатково встановлювати його не потрібно. Перевірка на Windows ARM64 ще не виконувалася.

Відкрий інсталятор і пройди майстер українською або англійською. Встановлення виконується для поточного користувача без прав адміністратора, типова папка — `%LOCALAPPDATA%\Programs\HelperBar`. Ярлик у меню «Пуск» додається автоматично, на робочому столі — за бажанням. Автозапуск самостійно не вмикається. Острів можна запустити наприкінці встановлення.

Наступну версію встановлюй поверх попередньої. Інсталятор коректно закриває острів перед оновленням; якщо програма не відповідає, встановлення зупиняється без примусового завершення. Новішу версію не можна випадково замінити старішою в тій самій папці. Видалення доступне у списку встановлених програм Windows і зберігає особисті дані в AppData.

Інсталятор поки не має цифрового підпису видавця. Публікація файлу в GitHub Releases і підключення завантаження на сайті — окремий крок; самі вихідні файли у гілці `helperbar` не є посиланням на завантаження інсталятора.

Для розробки можна й далі запускати `dist/HelperBar/HelperBar.exe` після `Build.ps1` або користуватися `Launch.cmd`. Така збірка потребує окремо встановленого .NET Desktop Runtime 10; копіювати слід всю папку, а не лише `.exe`.

Якщо бажаний екран недоступний, використовується основний; збережена прив’язка залишається. Фізичне від’єднання другого монітора та змішаний DPI ще потребують окремої перевірки.

## Налаштування

Відкрий **«Налаштування»** у верхньому меню. Розділи зліва залишаються на місці, прокручується лише права частина.

| Розділ | Що всередині |
| --- | --- |
| Профілі | «Моє», «Робота», «Музика», «Ігри», швидкий перехід до віджетів/оформлення та сповіщення активного режиму |
| Вигляд | Акцент і колір острова, очі, рідкий контур, зменшення руху, швидкість і сила декоративного руху, демонстрація емоцій |
| Музика | Мініплеєр, реакція на системний звук, чутливість, смуги, контур, підсвічування й баси |
| Пристрої | Віджет заряду, сповіщення про підключення й низький заряд, фільтри та оновлення |
| Ігри | Повний екран, приховування острова або лише очі |
| Позиція | Масштаб, відступ, повернення по центру й наступний монітор |
| Загальні | Автозапуск, наведення, секунди, звук таймера й гарячі клавіші |

Вибраний розділ зберігається між запусками, кожна секція пам’ятає свою прокрутку протягом сеансу. Кнопка «Налаштувати» у віджеті заряду відкриває відразу «Пристрої». Вибрані кольори позначені. «Повернути стандартний вигляд» скидає лише кольори, очі та рух; музика, позиція й загальні параметри залишаються твоїми.

У **«Загальні» → «Гарячі клавіші»** натисни поточну комбінацію, потім нові клавіші з Ctrl, Alt, Shift або Win. `Esc` скасовує введення. Якщо комбінація зайнята, попередня робоча залишається. Автозапуск початково вимкнений; він додається лише через перемикач.

У 0.8.0 пройдено 111 самоперевірок, рендер п’яти вкладок і всіх шести секцій, перевірки навігації, збереження параметрів та скидання вигляду. Повторно пройдено 17 інтеграційних перевірок сповіщень і 16 перевірок заряду через перенесені перемикачі. Звіти та зображення — `qa/0.8.0/`. Копія налаштувань перед оновленням — `data/settings-before-0.8.json`.

## Що реалізовано

- Прозоре вікно поверх інших вікон, компактний і розгорнутий стани та режим лише очей.
- Пружна зміна розміру з легким відскоком, переходи вкладок, реакції кнопок на наведення.
- Рідкий нижній край, хвиля від взаємодії, краплі, м’яке підсвічування й частинки.
- Погляд за курсором, моргання, м’яке дихання, автоматична дрімота після 22 секунд без руху курсора та пробудження.
- Радість, цікавість, здивування, сон, підморгування, запаморочення та святкування.
- Акцентні кольори, темні відтінки острова, масштаб, швидкість руху, відступ, режим зменшення руху.
- Годинник і дата, фактичне використання оперативної пам’яті та стан живлення.
- Поточна музика через медіасесії Windows: обкладинка, назва, виконавець, альбом, стан відтворення та прогрес. Кольори картки й підсвічування беруться з обкладинки.
- Вибір плеєра, адресні команди паузи / відтворення, попередній / наступний трек, перемотування, якщо плеєр дозволяє. Гучність та вимкнення звуку керують загальним виходом Windows.
- Повзунок гучності Windows `0–100%`, відсотки та окремий стан mute. Зміни з інших системних регуляторів надходять назад у картку; відсутній аудіовихід вимикає керування до відновлення.
- Компактна музична картка з обкладинкою та мініеквалайзером. Клік по ній відкриває вкладку «Музика». Очі залишаються поруч.
- 24 смуги спектра від справжнього WASAPI loopback: баси рухають рідкий контур та очі, рівень звуку керує підсвічуванням. Смуги затихають у тиші; випадкових значень або фіктивного руху під музику немає. Звичайна idle-анімація контуру окрема.
- Звичайний фокус-таймер із паузою та скиданням, а також до 12 окремих іменованих таймерів-нагадувань зі збереженням між запусками. Найближчий відлік показується у компактному острові; завершення — окремими картками з реакцією очей.
- Нотатка з автоматичним збереженням і окремий список справ із головною справою на сьогодні, відмітками виконання, редагуванням та скасуванням дії. Запуск Провідника, калькулятора та інструмента знімка Windows.
- Явні стани острова та коротка черга подій. Завершення таймера має пріоритет над гучністю; багато змін гучності об’єднуються в останнє повідомлення. Відкрита вручну вкладка залишається відкритою.

Це власна інтерпретація вигляду та поведінки, а не покадрова копія всіх переходів оригінальної програми. Слова пісень, погода, чати, запис екрана та керування Bluetooth/VPN ще не реалізовані.

## Твоя головна

**«Головна» → «＋ Додати»** відкриває чотири категорії:

- **Віджети:** годинник/дата, поточна музика, фокус-таймер, RAM/живлення, нотатка, системна гучність та заряд пристроїв. Музику й таймер можна поставити на паузу прямо з плитки. Натискання основної частини музики, фокусу або нотатки відкриває відповідну вкладку.
- **Програми:** пошук серед ярликів меню «Пуск» або ручний вибір `.exe`, `.lnk`, `.url`. Список не охоплює застосунки без ярлика в меню «Пуск»; їх можна вибрати вручну. Де доступно, плитка використовує локальну іконку програми.
- **Папки:** системний діалог вибору, власна коротка назва, відкриття у Провіднику.
- **Сайти:** власна HTTP/HTTPS-адреса або заготовки YouTube, YouTube Music і Spotify. Відкриваються у стандартному браузері. Адресу без протоколу, наприклад `music.youtube.com`, доповнюємо HTTPS.

**«Налаштувати»** дозволяє перетягувати плитки за `⋮⋮`, переміщувати їх стрілками та прибирати кнопкою `×`. Натисни назву ярлика в редакторі, щоб змінити його назву чи шлях. Кнопка **«↶ Скасувати»** повертає останню зміну розкладки; доступне й відновлення стандартної головної. Видалення плитки не видаляє програму або папку.

Розкладка зберігається автоматично, підтримує до 32 плиток і може залишатися порожньою. Недоступний файл/папка позначається теплим кольором; натискання відкриває редагування шляху. Віджети використовують наявний плеєр, таймер, нотатку та аудіосервіс — повторне відкриття головної не створює окремих екземплярів цих сервісів.

Початкова головна профілю «Моє» містить годинник, музику, Провідник, калькулятор, знімок, YouTube Music, фокус та стан ПК. Плитки, які не помістилися, доступні прокручуванням. Погода ще не реалізована.

## Профілі

На головній натисни **назву профілю зліва над плитками** й обери режим. Усі чотири картки вміщуються в острові. Другий шлях — **«Налаштування» → «Профілі»**. Зміни віджетів, оформлення та параметрів нижче автоматично записуються в активний профіль; останній вибір відновлюється після перезапуску.

| Профіль | Початкові віджети | Початковий характер |
| --- | --- | --- |
| Моє | Поточна розкладка користувача | Оформлення й параметри до оновлення збережені |
| Робота | Справи, фокус, нотатка, годинник | М’ятний акцент, стримані ефекти, без карток підключення та банера фокусу Windows |
| Музика | Музика, гучність, пристрої, годинник | Рожевий акцент, виразніші музичні реакції |
| Ігри | Стан ПК, гучність, пристрої, годинник | Блакитний акцент, слабкі декоративні ефекти, без реакції на звук; у повному екрані — лише очі |

Це стартові набори: кожен можна змінювати звичайними редактором головної та налаштуваннями. У «Профілях» кнопки «Віджети» й «Кольори й рух» відкривають потрібний розділ. Скидання вигляду та редагування розкладки стосуються тільки поточного режиму. Історія однієї дії «Скасувати» для розкладки очищується при перемиканні, щоб не перенести чужі плитки в інший профіль.

Окремо запам’ятовуються:

- Плитки, ярлики, порядок і порожня розкладка головної.
- Акцент, фон, очі, рідкий контур, зменшення руху, швидкість і **«Сила декоративного руху»** (0–150%). Останній повзунок змінює силу деформацій, дихання, наведення та кількість частинок; 0% залишає міміку й відкриття панелі, а «Зменшити рух» додатково прибирає переходи.
- Мініплеєр, реакція на системний звук, чутливість, смуги, контур, підсвічування та очі під музику.
- Сповіщення підключення/низького заряду, категорії пристроїв, картка виконаної справи, звук таймерів і банер Windows після завершення фокусу.
- Повноекранний тихий режим і вибір «Приховувати острів» / «Залишати лише очі».

У «Іграх» початково вимкнені картки підключення й виконаних справ, звук таймерів та банер фокусу Windows. Попередження низького заряду залишаються ввімкненими. Вимкнення картки справи залишає реакцію очей. Завершення таймерів зберігаються й показуються в острові; під час повного екрана чекають повернення. Перемикання не скасовує відлік і не відкидає його картку. Вимкнені за новими параметрами відкладені картки пристроїв/справ прибираються.

Спільними залишаються нотатка, справи, поличка файлів, таймери та тривалість фокусу, музична сесія, системна гучність і аудіовихід, позиція/масштаб острова, режим лише очей, відкриття наведенням, секунди годинника, автозапуск і гарячі клавіші. Вибір профілю не запускає програми та не змінює відтворення чи звук Windows. Автоматичного перемикання за грою/програмою, перейменування, дублювання й додавання профілів у цій версії немає.

Оновлення переносить поточні параметри до «Моє», включно з власними ярликами та порожньою головною. У `data/settings.json` блок `Profiles` містить `ActiveId` і чотири незалежні знімки. Поля попередньої схеми залишаються поточними значеннями активного режиму; перед збереженням і перемиканням вони копіюються до його знімка. Після завантаження відновлюється саме цей поточний стан; решта профілів перевіряються й зберігаються окремо.

`--profile-test --inspect` перевіряє реальні WPF-кнопки, незалежність оформлення/плиток, оновлення ресурсів і налаштувань, область дії скидання, спільні справи/файли/таймери та перезапуск. Тестові дані окремі, плеєр і системний звук не змінюються. Звіти й знімки — `qa/profile-integration.txt` і `qa/profiles-*.png`; міграція, виправлення пошкоджених даних і політика сповіщень входять до `--self-test`.

## YouTube, YouTube Music та Spotify

Запусти трек у браузері або Spotify. Коли плеєр публікує медіасесію Windows, острів автоматично покаже його дані. Якщо одночасно є кілька плеєрів, натисни назву джерела над назвою треку та обери потрібний. За замовчуванням пріоритет має активний плеєр, що відтворює звук.

Сторонній плеєр може не надавати обкладинку, тривалість або окремі команди — тоді показується нейтральна заглушка, а недоступні дії вимкнені. Для трансляцій без тривалості відображається «Наживо». Якщо браузер не публікує медіасесію Windows, сам звук усе одно може рухати спектр, але назву й обкладинку прочитати неможливо.

Спектр показує **весь звук стандартного вихідного пристрою Windows**, включно з іншими вкладками та сповіщеннями; це не ізоляція одного треку. При зміні стандартних навушників або колонок захоплення перепід’єднується. Звук, вручну спрямований у нестандартний вихід, може не потрапити до цього спектра.

У **«Налаштування» → «Музика»** є перемикачі «Музика у згорнутому острові», «Анімація від системного звуку», загальна чутливість та незалежні повзунки `0–150%` для музичних смуг, контуру, підсвічування й очей. Нуль вимикає відповідну реакцію на музику. Звичайні реакції на курсор залишаються; режим зменшення руху діє на анімації загалом. Вимкнення реакції на звук припиняє loopback-захоплення. Мікрофон не використовується.

Читання медіаданих та команди мають обмеження очікування. Для плеєрів із окремими можливостями Play/Pause використовується відповідна команда, навіть якщо Toggle не підтримується. Spotify працює за підтвердженням користувача; матриця всіх комбінацій кількох одночасних плеєрів поки не перевірена.

## Маленький список справ

Відкрий **«Нотатки» → «Справи»**, введи завдання й натисни **Enter** або **＋**. Нотатка залишається в сусідньому підрозділі й зберігає весь свій текст. Довжина справи — до 120 символів, список — до 100 записів разом із виконаними. Однакові назви дозволені: кожна справа має власну ідентичність.

- **☆ / ★** — закріпити або зняти головну справу на сьогодні. Одночасно закріплена лише одна активна справа; вона показується першою.
- **○ / ✓** — виконати справу або повернути її до активних. Виконання супроводжується реакцією очей і коротким повідомленням; виконані записи згортаються в окремий блок.
- **✎** — змінити назву у верхньому полі; Enter або ✓ зберігає, Esc / «Назад» скасовує редагування.
- **×** — видалити запис. **«Скасувати»** повертає останню зміну списку в поточному сеансі: додавання, назву, виконання, видалення або закріплення.

У **«Фокус» → «Зосередитись»** під відліком видно головну справу. Вона також відображається у віджеті фокусу. Для окремої плитки відкрий **«Головна» → «Додати» → «Віджети» → «Справи»**: там видно головне, кількість активних і виконаних записів та кнопку завершення. Наявна розкладка головної не змінюється автоматично. Завершення фокус-таймера не виконує справу замість користувача; дії зі справами не зупиняють фокус і нагадування.

Закріплення стосується поточного локального дня Windows. Наступного дня знімається лише зірочка; записи, порядок та виконання зберігаються. Виконана або видалена головна справа звільняє закріплення. Повернення виконаного запису до активних не закріплює його автоматично; скасування випадкового виконання відновлює сьогоднішнє закріплення. Скасування після зміни дня не повертає вчорашню позначку.

Додані справи автоматично зберігаються локально у `data/settings.json`. Чернетка у верхньому полі та історія однієї дії для «Скасувати» існують лише в поточному сеансі. Після перезапуску виконані справи не запускають повторну реакцію очей. «Зменшити рух» діє і на святкування виконання; окремого звуку або банера Windows для справ немає.

`--todo-test` перевіряє нативний інтерфейс: Enter/Esc, додавання, зірочки, редагування, виконання, скасування, віджет, зв’язок із фокусом, збереження нотатки й таймерів, зміну дня та довгі назви. Використовує приватні тестові налаштування. Звіт — `qa/todo-integration.txt`, знімки — `qa/todos-*.png`; моделі даних і відновлення входять у `--self-test`.

## Файли під рукою

Перетягни один або кілька файлів чи папок із Провідника на видимий острів, зокрема в режимі лише очей. Він розкриється із зоною «Відпусти файли тут». Якщо відвести курсор або скасувати перетягування, повернеться попередній стан. Внутрішнє перетягування плиток головної працює окремо.

Після відпускання відкривається **«Отримані»**. Біля кожного запису є три дії:

- **Папка** — показати вибраний елемент у Провіднику.
- **Копія** — скопіювати повний шлях. Для кількох файлів є «Скопіювати всі шляхи»: кожен шлях з нового рядка.
- **Плюс** — залишити посилання на поличці. «Залишити всі» додає всю отриману групу.

Поличку відкриває **«Головна» → «Файли · N»**. У ній `×` прибирає лише посилання. Вміст файлів не копіюється, не переміщується, не видаляється й не запускається автоматично. Збережені шляхи залишаються після перезапуску до ручного прибирання. Список «Отримані» існує тільки в поточному сеансі та замінюється наступним успішним перетягуванням.

Ліміт — **20 посилань** на поличці та до 20 різних шляхів в одному отриманні. Повтори об’єднуються без урахування регістру; зайві й непідтримувані записи показуються в лічильнику пропущених. Заповнена поличка не витісняє старі записи. Якщо файл перемістили або диск від’єднали, залишається позначка недоступності; шлях можна скопіювати чи прибрати. Файли з мережевих папок перевіряються у фоновому потоці з обмеженим очікуванням інтерфейсу.

Підтримуються наявні файлові шляхи Windows (`FileDrop`), зокрема папки. Посилання з браузера, текст, вкладення без збереженого файлу та віртуальні елементи архіватора не перетворюються на файли. Прихований або прозорий для кліків острів у повноекранному режимі не приймає перетягування; спочатку відкрий його звичайною гарячою клавішею.

`--file-drop-test --inspect` виконує перевірки панелі, скасування, полички, збереження, меж списку, недоступних файлів, копіювання та помилок Провідника. Тест має приватні налаштування й синтетичні файли; межі буфера обміну та відкриття папки підмінені тестовими діями, тому він не змінює користувацький буфер. Звіт — `qa/file-drop-integration.txt`, знімки — `qa/files-*.png`. Додатковий `--file-drop-inspect` залишає тестову картку для ручного жесту OLE; її немає у звичайному запуску. Модель полички перевіряється у `--self-test`.

Реальний жест OLE перевірено на картці із трьома тестовими елементами: отримано три шляхи, результат `Link`, оригінали залишилися на місці. Натискання «Показати в папці» відкрило вікно Провідника з тестовою папкою. Окремо ще не перевірено зовнішнє перетягування з усіх файлових менеджерів і фізичне від’єднання мережевого диска. Використано стандартні механізми [WPF drag-and-drop](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/advanced/drag-and-drop-overview) і [Windows Shell](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shopenfolderandselectitems).

## Таймери й нагадування

Відкрий **«Фокус» → «Таймери»**. Кнопки **«Чай · 5 хв»**, **«Перерва · 1 год»** та **«Рух · 30 хв»** запускають готові відліки. **«＋ Свій таймер»** відкриває форму з назвою й тривалістю. Приклади: `5 хв`, `1 год 30 хв`, `30 с`; число без одиниці означає хвилини. Діапазон — від 1 секунди до 24 годин, до 12 таймерів у списку. Можна мати кілька таймерів з однаковою назвою.

Кожна картка має паузу/продовження, запуск заново й видалення. Завершений таймер залишається зі станом «Готово»; ▶ повторює його початкову тривалість. У згорнутому острові показується найближчий активний відлік серед фокусу й нагадувань. Клік по компактному нагадуванню або його картці завершення відкриває список таймерів. Фокус у підрозділі «Зосередитись» та його віджет на головній продовжують працювати незалежно.

Завершення показує коротку картку з назвою та реакцією очей. Кілька одночасних завершень стають у чергу й не замінюють одне одного; навіть 12 нагадувань дочекаються показу. У відкритій панелі картка з’являється в заголовку без зміни вкладки чи введеного тексту. Звук регулюється у **«Налаштування» → «Загальні» → «Звук завершення таймерів»**. Нові нагадування не додають окремих банерів Windows.

Під час гри або повноекранного відео картки й звук відкладаються до повернення. Зберігаються абсолютний кінцевий час, залишок паузи та ще не показані завершення. Після сну або перезапуску прострочений таймер завершується, а вже показане нагадування не повторюється. Видалення або повторний запуск прибирає його стару картку з черги. Налаштування зберігаються локально у `data/settings.json`.

Нагадування показуються, коли HelperBar працює; закритий застосунок не запускається сам і не будить комп’ютер. Прострочені відліки з’являться після наступного запуску. Це таймери «через певний час»; будильники на дату/час, Pomodoro та відкладення «ще 5 хвилин» залишаються окремими майбутніми функціями. Старий одиночний фокус-таймер, на відміну від нових іменованих таймерів, поки скидається після закриття.

`--reminder-test` запускає нативні перевірки форми, паралельних відліків, паузи, повтору, видалення, збереження, реального завершення двох коротких тестових таймерів, черги, тихого режиму та розмірів інтерфейсу. Використовує окремі тестові налаштування без звуку. Звіт — `qa/reminder-integration.txt`, знімки — `qa/timers-*.png`; моделі часу й відновлення також входять до `--self-test`.

## Перемикання звуку

Натисни назву пристрою поруч із гучністю. Список показує активні виходи Windows із повними назвами; поточний позначений галочкою. Кнопка використовує коротку назву адаптера, повна доступна у підказці. На головній перемикач входить у віджет «Гучність», який можна додати через «Додати».

Підключені та відключені пристрої, перейменування й зміна стандартного виходу в Windows відображаються автоматично: список опитується щосекунди, одразу після відкриття та кнопкою ↻. Вибір змінює стандартні виходи **Console і Multimedia**; окремий пристрій для зв’язку **Communications** зберігається. Програми з власним явно заданим виходом можуть продовжувати використовувати його — це налаштовується в Windows або у відповідному плеєрі.

Гучність і mute підхоплюються з нового виходу, візуалізатор перепідключається автоматично. Поки триває перемикання, керування гучністю заблоковане; старі команди не застосовуються до нового пристрою. Якщо пристрій зник або Windows відмовила, показується помилка. Частково виконане перемикання намагається повернути попередні виходи; невдале відновлення повідомляється окремо. Порожній список пропонує підключити пристрій і дає перехід до налаштувань звуку Windows.

Перелік використовує [Windows Core Audio](https://learn.microsoft.com/en-us/windows/win32/coreaudio/device-properties). Зміна стандартного виходу ізольована у `WindowsAudioDevices` і використовує недокументований `IPolicyConfig::SetDefaultEndpoint` ([опис ABI у вихідному коді EarTrumpet](https://github.com/File-New-Project/EarTrumpet/blob/master/EarTrumpet/Interop/MMDeviceAPI/IPolicyConfig.cs)); сторонній застосунок або бібліотека не встановлюються. Успіх підтверджується повторним читанням обох ролей Windows. Перевірено реальне перемикання fifine SC3 → Realtek Audio → fifine SC3 на Windows build 26300, збереження гучності, mute та виходу Communications. Фізичне від’єднання Bluetooth-навушників під час перемикання ще не перевірене; зникнення пристрою та відмови перевіряються моделлю.

`--audio-probe` лише читає виходи й ролі у `qa/audio-probe.json`. `--audio-output-test` перевіряє справжній вибір виходу, синхронізацію гучності й спектра, обидві кнопки, довгі назви, прокрутку, порожній стан і помилки. **На кілька секунд перемикає звук на інший доступний вихід і відновлює початкові ролі у `finally`.** Якщо доступний лише один вихід, сценарій другого пристрою явно пропускається. Звіт — `qa/audio-output-integration.txt`, зображення — `qa/audio-*.png`. Для GUI-тестів спочатку закрий звичайний екземпляр HelperBar командою `--shutdown`.

## Локальні дані

Починаючи з 0.13.1 нотатка, налаштування, профілі, справи, таймери та шляхи полички зберігаються у `%LOCALAPPDATA%\HelperBar\data\settings.json`, окремо від програми. Нотатка записується звичайним текстом у JSON. Перед заміною зберігається остання придатна копія `settings.json.bak`. При пошкодженні або відсутності основного JSON читається резервна копія; пошкоджений файл при наступному збереженні залишається як `.corrupt`. Журнал помилок — `error.log` у цій самій папці.

Перехід зі старої збірки: закрий HelperBar, збережи копію старої папки `data`, онови програму до 0.13.1 у тій самій папці й запусти її один раз. Якщо AppData ще порожня, програма атомарно копіює придатний старий `data/settings.json` (або його резервну копію); оригінали залишаються. Потім можна встановити інсталятор у типову папку — він користуватиметься вже перенесеними даними. Інсталятор не шукає старі portable-копії по диску. Наявні дані в AppData мають пріоритет; при помилці перенесення програма використовує стару папку та показує повідомлення. Перед перенесенням на інший ПК окремо скопіюй папку даних.

HelperBar не має телеметрії чи сервісу завантаження файлів. Поличка записує лише шляхи у полі `Files` цього ж JSON; вміст файлів не читається. Для доданого мережевого шляху Windows може звернутися до відповідного файлового сервера, щоб перевірити доступність або показати папку. Увімкнення автозапуску створює лише власне значення `HelperBar.Personal` у `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`; вимкнення видаляє це значення. Команда посилається на поточну папку застосунку, тому після перенесення папки потрібно перемкнути автозапуск заново. Обкладинки надходять від Windows; аудіобуфер обробляється в оперативній пам’яті й не записується на диск.

## Збірка й перевірка

Потрібний .NET SDK 10 із компонентами Windows Desktop. Для WinRT медіасесій використовується офіційний Microsoft Windows SDK targeting pack з NuGet (автоматично через Windows TFM). Інших аудіобібліотек чи готових проєктів немає. TFM використовує API Windows build 19041, а інсталятор вимагає Windows 10 22H2 (19045) або новішу.

Для інсталятора також установи [Inno Setup 7](https://jrsoftware.org/inno-setup/downloads), потім:

```powershell
.\Build-Installer.ps1
# Або вкажи власний шлях до компілятора:
.\Build-Installer.ps1 -CompilerPath 'C:\Tools\Inno Setup 7\ISCC.exe'
```

Скрипт публікує свіжу `win-x64` self-contained збірку без trimming, додає ліцензії використаних runtime-пакетів, запускає самоперевірки й компілює інсталятор. Папки `data` / `qa`, журнали й PDB до пакета не входять. Результат: `artifacts/installer/HelperBar-Setup-x64.exe`, `SHA256SUMS.txt`, `build-info.json` та `payload-manifest.json`. Для тестового встановлення з окремими назвою, ярликами та AppId додай `-InstallerTest`; подробиці — [installer/README.md](installer/README.md).

```powershell
dotnet build .\HelperBar.csproj -c Release
dotnet publish .\HelperBar.csproj -c Release --no-self-contained -o .\dist\HelperBar
dotnet .\dist\HelperBar\HelperBar.dll --self-test
dotnet .\dist\HelperBar\HelperBar.dll --smoke-test
dist\HelperBar\HelperBar.exe --music-test --inspect
dist\HelperBar\HelperBar.exe --daily-test --inspect
dist\HelperBar\HelperBar.exe --home-test --inspect
dist\HelperBar\HelperBar.exe --audio-probe
dist\HelperBar\HelperBar.exe --audio-output-test --inspect
dist\HelperBar\HelperBar.exe --reminder-test --inspect
dist\HelperBar\HelperBar.exe --todo-test --inspect
dist\HelperBar\HelperBar.exe --file-drop-test --inspect
dist\HelperBar\HelperBar.exe --profile-test --inspect
```

`--self-test` перевіряє анімації, фокус і кілька таймерів, Unicode-нотатки, список справ і щоденне закріплення, поличку файлів, міграцію та резервне відновлення, PCM/FFT, таймлайн, координати монітора, конфлікти клавіш, повідомлення, порядок плиток, валідацію ярликів, збереження розкладки, батареї, сповіщення пристроїв, повноекранну поведінку й перемикання аудіовиходів із відмовами. Результати — у `qa/self-test.txt` поруч із застосунком.

`--smoke-test` відкриває тестове вікно, рендерить усі вкладки, компактний режим, очі й сповіщення в `qa/`, потім закривається. Нотатки й налаштування користувача не змінює. Перед цим закрий звичайний екземпляр.

`--inspect` додає вікно до панелі задач, щоб інструменти UI Automation могли вибрати його під час перевірки. Звичайний запуск залишає тільки острів і трей.

`--music-test` створює власний тихий локальний WAV та тестові обкладинки, реєструє справжній плеєр Windows, перевіряє читання метаданих, loopback, паузу, перемотування, зміну треку й відновлення. Керує лише своїм тестовим плеєром. Звіт і рендери — `qa/music-integration.txt` та `qa/music-*.png`.

`--daily-test` перевіряє реальні координати вікна, реєстрацію клавіш, повзунок гучності, mute та зміни з незалежного Core Audio клієнта. **На кілька секунд змінює системну гучність і mute, потім відновлює їх у `finally`.** Не змінює користувацькі налаштування й автозапуск. Звіт із 9 перевірок — `qa/daily-integration.txt`, рендери — `qa/daily-*.png`.

`--home-test` виконує 17 перевірок головної: спільний таймер, форми ярликів, видимий текст, редагування/скасування, живі нотатка й гучність, відновлення розкладки та порожній стан. Читає ярлики меню «Пуск», але не запускає додані цілі та не змінює системну гучність. Результати — `qa/home-integration.txt` і `qa/home-*.png`.

`--media-probe` виконує читання поточної медіасесії та аудіорівня без зміни відтворення; діагностика з назвою треку залишається локально у `qa/media-probe.json`. `--shutdown` коректно завершує запущений HelperBar зі збереженням налаштувань.

Перевірено запуск на цьому ПК, відкриття кліком і гарячою клавішею, вкладки, старт/паузу/скидання таймера, редагування й збереження нотаток, зміну кольору, прокручування та демонстрацію реакцій. Перенесення між моніторами з різним DPI та взаємодія медіаклавіш з усіма сторонніми плеєрами окремо не перевірялися.

Музичні перевірки: 16 перевірок справжньої медіасесії Windows та loopback пройдено, включно з віджетом головної та його кнопкою паузи; раніше на активному треку в Opera підтверджено метадані, стан і ненульовий спектр. Spotify підтвердив користувач 21 листопада 2026. Перепід’єднання фізичного аудіопристрою, вхід у Windows з увімкненим автозапуском та змішаний DPI окремо не тестувалися.

Звіти та вибрані рендери головної збережено в кореневій папці `qa/0.4.0/`; перевірки попереднього пакета залишені у `qa/0.3.0/`.

Після запуску 0.4.0 окремо звірено збереження реальної нотатки, акценту, масштабу, позиції й гарячих клавіш. Налаштування мігровані до схеми 2; початкову розкладку створено без зміни цих даних.

## Заряд пристроїв

**«Налаштування» → «Пристрої» → «Показувати заряд пристроїв на головній»** додає віджет на початок головної. У блоці «Типи пристроїв» окремо вмикаються мишка, клавіатура й навушники. Альтернативний шлях — **«Головна» → «＋ Додати» → «Віджети» → «Заряд пристроїв»**. Плитку можна пересунути звичайним редактором. Видалення плитки зупиняє опитування, якщо обидва типи сповіщень також вимкнені; віджет і сповіщення використовують один сервіс. Оновлення саме не додає плитку до твоєї головної.

Показуємо назву, іконку, реальні відсотки й анімовану смугу; 20% і нижче виділяються теплим кольором. Автооновлення — кожні 5 секунд, є ручна кнопка «Оновити». Підключений Bluetooth-пристрій без доступного відсотка показує «Заряд недоступний». Вимкнені, від’єднані та сплячі пристрої прибираються після наступного опитування. При помилці читання старі відсотки очищуються. Заряджання та залишок часу не вгадуються.

Джерела: властивості Windows для підключених Bluetooth LE / Classic пристроїв; запасне читання стандартного BLE Battery Service. USB/2.4 ГГц пристрої додаються, лише якщо драйвер публікує батарею в Windows. Фірмові протоколи USB-приймачів не реалізовані, тому підтримка всіх моделей не гарантується. Офіційні описи: [BatteryLife](https://learn.microsoft.com/en-us/windows/win32/properties/props-system-devices-batterylife), [властивості пристроїв](https://learn.microsoft.com/en-us/windows/apps/develop/devices-sensors/device-information-properties), [GATT client](https://learn.microsoft.com/en-us/windows/apps/develop/devices-sensors/gatt-client).

На цьому ПК 21 листопада 2026 прочитано **AJ159 PRO — 100% через Bluetooth**. Старий неактивний запис тієї ж моделі не потрапив у список. До пробудження мишки та під час наступного тесту Windows повідомляла про неактивне підключення — список був порожній. Фізичні клавіатура, Bluetooth-навушники й USB-приймач із батареєю ще потребують перевірки.

`--battery-probe` читає реальні пристрої без інтерфейсу й зберігає локальний `qa/battery-probe.json`. `--battery-test` перевіряє справжній інтерфейс налаштувань/віджета, доступність Windows API, вимкнення/повторне ввімкнення, скасування видалення, очищення застарілих даних і запізнілі відповіді. Звіт — `qa/battery-integration.txt`; зображення з `fixture` у назві містять явно позначені тестові пристрої, решта — фактичний стан Windows. Тести використовують окремі налаштування.

У 0.5.0 пройдено **68 самоперевірок**, **16 інтеграційних перевірок заряду**, **17 перевірок головної** та рендер усіх вкладок. Після оновлення звірено збереження нотатки, вигляду, позиції, клавіш і всієї розкладки; резервна копія — `data/settings-before-0.5.json`. Звіти й вибрані зображення — `qa/0.5.0/`.

## Сповіщення пристроїв

**«Налаштування» → «Пристрої» → «Заряд і сповіщення»** містить незалежні перемикачі **«Сповіщати про підключення»** та **«Попереджати про заряд 20% і нижче»**. У початковому «Моє» обидва ввімкнені й працюють без віджета головної; інші профілі мають свої параметри. Фільтри мишки, клавіатури й навушників спільні для віджета та сповіщень усередині активного профілю.

Після підтвердженого підключення острів на 4,5 секунди плавно стає невеликою карткою: іконка, назва, відсоток і смуга заряду; очі радіють. При 20% і нижче з’являється тепле попередження й здивована реакція. Невідомий заряд прямо позначений як недоступний. Відкрита вручну сторінка не закривається: картка займає лише заголовок, введення нотатки та фокус іншої програми не перехоплюються. Натискання по компактній картці поруч з очима відкриває головну з віджетом або налаштування, якщо віджета немає.

Перший успішний знімок після запуску мовчки запам’ятовує вже підключені пристрої; уже низький заряд усе ж попереджає один раз. Після сповіщення про низький заряд повтор можливий лише після показника 25% або вище й нового падіння до 20%. Цей захист зберігається в поточному сеансі через сон, перепідключення та вимкнення/увімкнення опції. Для підключення є хвилина захисту від повторів на кожен пристрій; одна пропущена перевірка або помилка Windows не вважається перепідключенням. Пристрої з однаковою назвою розрізняються за ідентичністю.

У повноекранному режимі повідомлення відкладаються. Заряд у черзі оновлюється; після від’єднання пристрою або відновлення заряду неактуальна картка скасовується. Завершення таймера має вищий пріоритет. Звуків або системних банерів для цих двох нових подій немає. Підтримуються пристрої, які вже бачить сервіс заряду; фірмові протоколи USB-приймачів не додані.

`--device-notice-test` виконує 17 інтеграційних перевірок: справжнє читання Windows, окремі перемикачі без віджета, компактну й розгорнуту картки, реакції, невідомий заряд, відкладення й скасування неактуальних подій. Усі візуальні сценарії підключення/20% використовують явно позначені тестові пристрої; реальне розряджання або фізичне перепідключення в цьому пакеті не перевірялися. Разом пройдено 111 самоперевірок, повторно 16 перевірок батарей, 16 музики та рендер усіх вкладок. Звіти — `qa/0.7.0/`, резервна копія налаштувань — `data/settings-before-0.7.json`.

## Ігри й повний екран

**«Налаштування» → «Ігри» → «Не заважати у повному екрані»**. Початково увімкнено **«Приховувати острів»**; альтернативний варіант — **«Залишати лише очі»**. Очі пропускають натискання миші до програми під ними й не відкривають панель від наведення. Вимкнений перемикач залишає звичайну поведінку острова.

Режим працює, коли активна програма займає весь монітор, де розташований острів. Звичайне максимізоване вікно, робочий стіл та повний екран на іншому моніторі не повинні його вмикати. Короткі зміни фокусу згладжуються: вхід приблизно за 0,5 с, повернення — приблизно за 0,75 с. Після виходу або Alt+Tab повертаються попередній компактний/розгорнутий вигляд і збережений режим очей, без перехоплення фокусу. Ручне «Приховати у трей» не скасовується автоматично.

**Ctrl+Alt+Space** (або власна комбінація) тимчасово відкриває острів навіть під час повного екрана. Повернення до гри чи закриття панелі повертає тихий режим. Трей також дозволяє відкрити налаштування.

Сповіщення острова відкладаються, повтори об’єднуються; черга містить до чотирьох звичайних подій плюс завершення всіх іменованих таймерів. Відліки тривають, картки дочекаються повернення. Для старого фокус-таймера також відкладається повідомлення в треї. Звук і банер залежать від параметрів активного профілю на момент показу. Це налаштування HelperBar, воно не змінює системні сповіщення інших програм.

`--fullscreen-test --inspect` запускає власне тестове вікно Windows: звичайне, максимізоване й без рамки на весь екран. Якщо Windows відмовила у фокусі фоновому процесу, протягом хвилини активуй вікно «HelperBar — перевірка повного екрана». Після перевірок воно закриється. Звіт — `qa/fullscreen-integration.txt`. Графічні тести повертають код 2, якщо вже працює інший екземпляр, замість хибного успішного результату.

У 0.6.0 перевірено **18 нативних сценаріїв** на моніторі 2560×1440 при 100% DPI, **84 самоперевірки**, повторно **17 перевірок головної**, **16 батарей**, **16 музики** та рендер усіх вкладок. Негативні координати/інший екран перевірені моделлю; конкретні ігри з ексклюзивним DirectX-режимом та фізичні монітори з різним DPI ще не перевірялися. Звіти й зображення — `qa/0.6.0/`. Попередні налаштування — `data/settings-before-0.6.json`.

Виявлення спирається на [GetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getforegroundwindow), [GetClientRect](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getclientrect), [ClientToScreen](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-clienttoscreen) і стан DWM. Острів не під’єднує код до ігор і не читає їхній вміст.
